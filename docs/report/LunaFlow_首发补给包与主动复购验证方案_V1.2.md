# LunaFlow｜首发补给包与主动复购验证方案 V1.2

日期：2026 年 9 月 23 日。配套演示：[PPT 网页](../cover.html)。

**本版决策：用一份可交付、可算账的经期用品补给包验证首单与主动复购，再分别验证经期工具和数字会员。**

本文补充 V1.1 的商业验证顺序，不替换其记录、AI 确认、关怀授权等产品边界。全部价格、成本、预算和试验安排均为设计假设，不代表已取得报价、完成开发、获得准入或验证经营效果。

## 1. 为什么先做补给包

首轮目标是验证短链路、小投入的交易是否成立。用户先看清具体用品、到手价和售后，再决定购买；不必先理解会员权益、完成健康记录或绑定伴侣。

用户把承诺的权益全部用掉，平台仍应有贡献；用户知道下一次价格，仍愿意主动购买。预收款对应未来履约义务，不能直接当利润。权益未使用、暂时没有需求、忘记取消是不同情况，不合并为收入增长依据。

| 层次 | 作用 | 独立验证问题 |
| --- | --- | --- |
| 商品补给 | 提供首单购买理由 | 相同品牌、规格和运费条件下，用户为什么选我们 |
| 补货服务 | 减少再次选购的操作 | 保存常用组合和提醒是否促进主动复购 |
| 经期工具 | 记录与回顾个人信息 | 用户是否愿意独立使用，是否减少记录负担 |
| 数字会员 | 收费提供额外数字服务 | 用户是否愿意为明确服务持续付费 |

用品复购不等于工具有效，也不等于数字会员成立。若用户只购买用品，可继续评估商品经营机会；是否继续投入 AI 会员需另作判断。

## 2. 首发人群与任务

优先研究成年、已有用品偏好、近期需要补货的用户。她们希望买对规格、看清到手价、减少重复挑选。首轮不假定所有人每月采购，也不以年龄、焦虑或取消困难推断付费意愿。

购买任务是“买到适合自己的用品”，记录任务是“方便地记录与回顾”。两者可以关联，但不得互相强制。

## 3. 首发包：只承诺能够兑现的内容

| 项目 | 首轮方案 |
| --- | --- |
| 工作名称 | LunaFlow 经期用品补给包 |
| 实物主权益 | 一份明确品牌、规格、片数的原包装日用／夜用组合 |
| 价格 | 暂以 39.9 元／次测算，须根据商品价值、真实供价和履约成本重算 |
| 组合数量 | 一个组合起步，不宣称适合所有用户或足够使用一个周期 |
| 配套服务 | 保存常用规格、按上次组合再次购买、用户自选补货提醒 |
| 工具体验 | 自愿使用基础经期记录；有真实记录后再体验 AI 整理或回顾 |
| 供应方式 | 优先洽谈一家供应商代发，先不囤货、不定制包装；能力待核实 |
| 付款方式 | 按次购买，再次购买需用户自主确认付款 |

每个商品页应明确实际交付内容、最终到手价、配送条件和售后规则。不得把公开渠道本来就有的优惠称为独占权益。AI、通知或其他服务只有在实际可用时才列入交付承诺。

首轮不扩展家政、体检、宠物等跨行业权益；9.9 元 AI 会员、伴侣关怀等历史方案保留为后续独立实验。

## 4. 一条成交链路，两项自愿选择

首单：**广告 → 商品详情 → 一次付款 → 供应商履约 → 收货与售后。**

成交后，用户可自愿保存常用组合、选择补货提醒；也可独立使用经期记录工具。填写经期、体验 AI 和绑定伴侣均不作为购买前置条件。

复购：**用户自选提醒或主动回来 → 查看上次组合与本次价格 → 调整规格／跳过／推迟 → 自主确认付款。**

补货时间由用户选择，不把周期预测日期直接当成营销触发条件。付款、分享、AI 处理和消息订阅分别授权；对方代付不授予健康信息查看权。未购买、未分享或未订阅通知，仍可使用基础记录。

首轮不依赖自动续费。后续仅在存在真实需求、履约稳定且相关能力可用时，将定期配送或自愿续费作为可选便利功能另行验证。

## 5. 单位经济：先确定谁收钱

### 5.1 平台收取商品款的测算示例

下表假设平台承担商品采购和履约相关成本，**全部为待验证参数**：

| 项目 | 每单金额 |
| --- | ---: |
| 商品售价 | 39.9 元 |
| 商品采购 | −18.0 元 |
| 包装、拣货和物流 | −5.0 元 |
| 支付、税费、客服及退款净损耗 | −2.5 元 |
| 配套数字服务 | −1.5 元 |
| **投流前单笔贡献** | **12.9 元** |

12.9 元不是净利润，仍需扣除获客与固定成本。2.5 元综合费用也需按实际经营主体、结算和订单拆分核实；不得将退款本金与退货净损耗重复计入。

| 情景 | 首单扣获客后贡献 | 含义 |
| --- | ---: | --- |
| CAC 为 10 元 | 2.9 元 | 尚需覆盖固定成本，不能据此直接认定盈利 |
| CAC 为 20 元 | −7.1 元 | 首单亏损，不能靠未验证续费预期放量 |
| 成本增加 5 元 | 投流前剩 7.9 元 | 应同步下调可承受获客成本 |

这些数字是算账示例，不是批准投放的固定门槛。可承受 CAC 应从真实贡献、固定成本分摊和资金约束倒推，并在投放前写明。

### 5.2 商家收款、平台拿佣金时

若由商家直接收款，39.9 元是商品成交额，不是平台收入。

**平台单笔贡献＝实际可结算佣金−平台承担的服务、补贴、售后等变动成本。**

投放前明确交易主体、收款方、供货方、发货方、售后责任、退款承担与结算周期。每轮试验只使用与实际合作一致的一个经济模型，不混用商品收入和佣金收入。

## 6. 供应选择先于投流

比较三家候选供应商，至少完成一次真实下单。现有美业资源不能直接视为已落实卫生用品货源。

| 需要拿到的信息 | 决策用途 |
| --- | --- |
| 品牌、规格、片数、商品与授权资料 | 确认交付内容和供货来源 |
| 同款公开到手价及条件 | 判断用户是否有合理购买理由 |
| 首单和老客可持续供价 | 排除只能靠一次性补贴成交的假象 |
| 拣货、包装、运费和偏远地区费用 | 算出完整履约成本 |
| 库存、发货时间和缺货处理 | 判断承诺能否兑现 |
| 退换、质量问题和客服分工 | 确认损耗与售后责任 |
| 结算周期、垫资和退款安排 | 估算真实周转资金 |

拿不到持续价格优势，就必须验证“省去挑选和补货操作”是否值得付费；两者都无法成立，停止这个包的投流设计。

## 7. 小额试验与资金安排

在已有可用交易工具、经营主体和基本条件的前提下，先用允许该业务的现成工具验证交易，不以完整小程序开发作为首轮投放前提。平台准入、起投和充值要求按实际账户核实。

| 增量试验用途 | 上限建议 |
| --- | ---: |
| 样品、真实下单与同款比价 | 300 元 |
| 简单素材与商品页制作 | 300 元 |
| 广告消耗 | 1,000 元 |
| 售后及实验预备 | 400 元 |
| **增量试验费用合计** | **2,000 元** |
| **另备周转资金** | **约 1,500 元** |

预计资金准备约 3,500 元，其中周转资金用于垫付和结算错期，可循环使用，不是额外广告预算，也不保证足以覆盖所有退款情景。按实际结算周期调整，避免与预算中的已确认售后损耗重复计费。本预算不含从零开发小程序的人工成本，也不保证特定订单或样本量。

试验顺序：

1. **供应验证：**落实具体组合、交易责任与报价，完成真实下单，重新计算贡献。
2. **首单验证：**一个组合、一个供应商、一条付款链路；固定价格与页面，先比较“规格与到手价”和“按常用组合省事补货”两种表达，分批消耗预算。
3. **复购观察：**持续观察同一批用户 60—90 天，记录再次购买机会、主动复购和工具使用。未到补货时间的用户不直接归为流失。

30 天首单结果不能证明长期 LTV，60—90 天也只是初步复购证据。小预算可能只够排除明显问题；样本不足应记录为“证据不足”，不通过调换分母或合并不同人群制造结论。

## 8. 指标与继续、调整、停止

投放前固定统计口径、观察窗口、最大可承受亏损和渠道归因规则，避免看见结果后再改标准。

| 指标 | 统计口径与作用 |
| --- | --- |
| 真实单笔贡献 | 按订单计入实际收入、采购、履约、服务与净退款损耗；用于判断交易本身是否成立 |
| 广告 CAC | 广告消耗除以同一归因口径下有效新购买用户数，剔除全额退款订单；样本与退款窗口同时披露 |
| 主动复购 | 按首购批次观察第二次自主确认付款，披露人数、分母与观察时长；不混入自动扣款 |
| 工具使用 | 独立统计自愿启用、记录和回顾使用；不将购买或打开订单页算成工具活跃 |
| 数字会员意愿 | 后续用明确价格和服务范围独立验证，不把赠送体验或实物复购算成会员付费 |

| 决策 | 依据与动作 |
| --- | --- |
| 继续小额验证 | 供货与售后可兑现，真实贡献可接受，获客表现处于预设承受范围；继续观察复购，不急于放量 |
| 调整一项再验证 | 商品价值有迹象，但素材、转化、规格或成本有明确问题；保持其余条件，限定剩余预算 |
| 暂停并修复 | 履约、质量或退款出现明确问题；先完成已售订单的处理，再判断是否恢复 |
| 停止该组合 | 无持续供价或服务价值，成本／获客亏损无法改善，或已触及预设亏损上限 |
| 证据不足 | 订单太少、退款窗口未结束或补货机会尚未出现；只陈述已观察事实，不宣布成功或失败 |

获客、复购和工具留存应分开看。若用品复购良好但工具几乎不使用，应重新判断项目是商品经营还是工具产品，而不是默认 AI 会员得到验证。

## 9. 后续产品顺序与历史方案关系

当前顺序：**供应证据 → 首单成交 → 主动复购 → 工具独立价值 → 数字会员独立付费 → 可选自愿续费与扩大投流。**

基础工具可以同步做低成本验证，但不阻塞首单试验；数字会员和伴侣关怀不进入本轮承诺。后续是否增加自动续费，要依据用户便利需求、相应能力和新的实验结果，不以忘记取消或限制退出创造收益。

V1.1 的记录、回顾、双端角色与权限设计继续作为参考。其会员价格、权益券、成本示例与旧验证顺序属于历史设计，不应与本次 39.9 元商品假设相加或混用。

PPT 前 8 页展示本版商业验证方案，后 8 页保留原研报及 V1.0／V1.1 图稿。历史资料说明研究和设计过程，不证明 LunaFlow 已有相应规模、功能或经营结果。

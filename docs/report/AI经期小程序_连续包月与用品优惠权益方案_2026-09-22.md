# AI 经期小程序：连续包月与用品优惠权益方案

> **一句话定位：用极简记录与 AI 整理帮助用户省心，用真实可兑现的用品优惠帮助用户省钱；先验证单次月卡，再开放自愿连续包月，最后放大投流。**

| 文档信息 | 内容 |
| --- | --- |
| 版本 | V1.0 |
| 整理日期 | 2026 年 9 月 22 日 |
| 适用场景 | 面向中国大陆成年用户的微信小程序产品讨论与立项验证 |
| 方案范围 | 极简记录、AI 辅助整理、月卡会员、连续包月、合作商家用品优惠券 |
| 内容性质 | 基于本轮讨论整理的产品与商业方案，不是已经验证的经营结果 |
| 尚未落实 | 实际商户准入、各端支付能力、合作商家报价、优惠库存、转化率与续费率 |
| 数字说明 | 9.9 元月费、成本、补贴、核销率及测试预算均为实验或测算示例，不是市场报价或收益承诺 |

## 一、结论：可以组合，但应先验证权益，再签约续费

建议采用：

**极简 AI 记录工具 + 每月自选用品优惠权益 + 用户主动选择的连续包月。**

这个组合增加了更直观的付费理由，但不能仅凭“每月送券”认定商业模式成立。需要同时证明：

1. **工具有用：**用户真的更容易记录、回顾自己的信息，而不只是为了领券打开。
2. **优惠真实：**用户买原本需要的商品时，能获得额外优惠，而不是被高门槛或运费抵消。
3. **经营可持续：**扣除权益补贴、AI、客服、退款损耗及获客成本后，仍有合理贡献。

**不建议的模式：**用“免费领券”隐藏自动续费；用健康焦虑促成购买；靠忘记领券、忘记取消维持利润；先承诺长期权益，再寻找供应商补缺。

## 二、用户价值：省心、省钱、可控

| 用户任务 | 产品交付 | 不应做的事情 |
| --- | --- | --- |
| 快速记下开始、结束或补录日期 | 一键记录，随时修改 | 为简单操作强制打开 AI 对话 |
| 想记录腹痛、睡眠、情绪等感受 | 一句话整理成待确认的结构化记录 | 猜测用户没有提供的症状或程度 |
| 回顾过去发生过什么 | 可追溯的时间线、统计与摘要 | 将相关性描述为病因，自动诊断 |
| 购买原本就需要的用品 | 自选适用的合作券，显示完整条件与到手价 | 用临期券逼迫囤货，或者推销无关商品 |
| 控制服务和数据 | 清晰的付费周期、续费提醒、取消入口、数据管理 | 将取消续费与删除记录、停止当期权益绑定 |

产品对外表达建议：

> **简单事情一键记，复杂感受一句话整理；需要买用品时，再来选一张合适的优惠券。**

既然引入商业权益，就不宜继续承诺“完全没有商业推广”。更准确的表达是：**不做干扰式广告，不把商品推销混入健康记录与 AI 摘要，用品权益放在独立入口，由用户主动选择。**

## 三、首版会员方案：9.9 元／月仅作为测试价格

### 3.1 免费基础与付费增强分开

| 服务 | 免费基础 | 月卡会员增强 |
| --- | --- | --- |
| 经期日期记录 | 一键开始、结束、补记、修改 | 不重复包装为付费专属能力 |
| 历史记录 | 基础查看与导出 | 跨周期整理、指定时间范围的摘要 |
| AI 整理 | 有限体验，允许不用 AI | 更多整理额度或更完整的整理工作流，具体限额另行测试 |
| 就诊准备 | 保留原始记录 | 用户可编辑、可核对的资料摘要，不提供诊断 |
| 用品优惠 | 可展示真实权益条件 | 每个已支付账期可自选一张已落实的合作优惠券 |
| 数据控制 | 查阅、纠错、注销及符合条件的删除等，不设会员门槛 | 不以限制迁移制造续费 |

涉及个人信息权利，应结合实际功能落实；医疗健康信息的处理也有更严格的要求。[R1]

### 3.2 支付选项

**首期先做单次月卡。**在支付权限、续费提醒、取消与退款流程全部跑通后，再提供主动签约的连续包月。

| 选项 | 用户承诺 | 产品行为 |
| --- | --- | --- |
| 单次月卡 | 仅购买一个账期 | 到期不自动扣款，历史记录仍按原规则可访问 |
| 连续包月 | 在明确授权下，按展示的周期和金额续费 | 每次支付成功后延长权益并发放当期领券资格 |

**“签约成功”不等于“扣款成功”；不得仅凭签约就认定当期会员已经付款。**

### 3.3 用品券规则

按付费账期发放资格，不按月经预测日期触发营销。建议每期自选一张，而不是堆叠多张高门槛券。

权益页至少展示：合作商家、品牌及适用商品、满减或折扣门槛、有效期、新老客限制、运费、叠加规则、使用入口、售后主体。

有效期和延期领取安排应先与商家约定。可以研究更灵活的使用窗口，但在未落实前，不承诺券可跨月累积、永久有效或随时补发。

**用户不一定每月购买用品。应允许不领取、不使用，避免用过期压力强迫消费。**

## 四、供应链与商家合作：先拿到真优惠，再卖会员

### 4.1 三种优惠出资方式

| 合作方式 | 优惠成本承担 | 建议 |
| --- | --- | --- |
| 商家出资 | 品牌或授权商家提供专属价格或优惠 | 优先争取，仍需比较实际到手价 |
| 共同补贴 | 商家让利，平台按核销追加有限补贴 | 小规模测试，设总预算和单用户上限 |
| 平台独补 | 平台承担主要优惠金额 | 谨慎；防止规模越大、亏损越大 |

首版建议集中在少量常规经期用品，不扩展为百货商城，也不把药品或疗效承诺混入会员权益。

### 4.2 合作协议应明确的事项

| 项目 | 必须确认的内容 |
| --- | --- |
| 商家身份 | 主体、授权与履约能力，商品及售后责任 |
| 优惠真实性 | 同款规格、数量、包装和含运费到手价；是否只是公开渠道通用券 |
| 用户限制 | 新客、老客、地域、购买数量、账号或设备限制 |
| 可持续性 | 供券周期、库存、月度额度及是否续签；不能用一次性新客优惠替代长期权益 |
| 资金结算 | 谁承担折扣、何时结算、退款如何追回佣金或补贴 |
| 商家退出 | 已承诺权益如何继续兑现、替换或合理处理 |
| 信息交换 | 仅提供完成领券与核销所必需的信息，不交换症状、经期或病史用于营销 |

### 4.3 券面额不等于实际省钱

以下为示例：

```text
同款公开渠道价格：39.9 元，包邮
合作店铺价格：49.9 元
会员优惠券：减 10 元
券后到手价：39.9 元，包邮

用户相对公开渠道额外节省：0 元
```

**判断标准是同款商品可实际买到的到手价，而不是券面额。**

在没有稳定、可复核的依据时，不宣传“每月一定省回会员费”“全网最低价”或“每位会员都能省多少”。

## 五、交易结构：会员支付与用品购买分开

```text
会员服务线
用户选择月卡／主动签约
       ↓
当期会员支付成功
       ↓
平台开通 AI 增强权益 + 发放当期领券资格
       ↓
用户主动选择并领取合作券

用品订单线
用户在明确展示的合作商家使用优惠
       ↓
用户单独支付商品订单
       ↓
合作商家发货、处理商品售后
       ↓
按约定核销、结算优惠与佣金
```

平台仍需负责自身会员承诺、领券故障与合作协调，不能因商品由第三方履约就推卸全部责任。

### 5.1 从轻量合作开始

可先研究专属券码和商家已有合规使用入口，再根据合作规模评估商家券接口。腾讯相关资料可以作为能力调查入口，但文档存在不等于本商户具备所有权限，也不代表券可在任意微信商家通用。[R3]

任何跳转、核销和支付方案，都应按小程序实际支持能力、主体关系与平台规则验证，不能先承诺任意跨商家使用。

### 5.2 后台需要分开的状态

| 对象 | 示例状态 | 原则 |
| --- | --- | --- |
| 续费协议 | 未签约、有效、已取消 | 协议只表示授权，不等于付款 |
| 会员账期 | 未付款、已生效、到期、退款处理中 | 以实际支付和退款状态处理权益 |
| 领券资格 | 未发放、可领取、已领取 | 每笔有效账期仅发放一次 |
| 优惠券 | 未使用、已核销、过期、撤销处理中 | 依据券规则及商家返回结果处理 |
| 商品订单 | 待支付、已支付、履约中、已完成、退款 | 与会员订单分离管理 |

支付通知需做幂等处理，避免重复开通或重复发券。取消续费不应等于立即撤销已付账期。遇到已核销优惠后的退款，应按事前清晰、合理的规则处理，不简单规定“领取赠品后一律不退”。

## 六、单位经济：按真实核销与成本测算

### 6.1 基础公式

```text
每位付费会员每账期贡献
= 实际确认的会员收入
− 支付／渠道、退款损耗、AI、客服等直接成本
− 每位会员的期望平台优惠补贴成本
+ 已结算且扣除退款追回后的佣金
```

对于每账期最多使用一张、每次平台补贴固定金额的示例：

```text
期望平台优惠补贴成本 = 每张实际补贴 × 核销率
```

这里的贡献不是净利润，尚需覆盖获客、研发、合规、固定人员及未纳入的其他费用。退款应统一会计口径，避免在净收入与成本中重复扣除。

### 6.2 示例参数

| 参数 | 示例值 | 说明 |
| --- | --- | --- |
| 会员费 | 9.9 元／月 | 测试价格，非已验证定价 |
| 直接成本合计 | 2 元／人／月 | 示例汇总，不是微信费率或模型真实报价 |
| 单张券平台补贴 | 3 元／次核销 | 不等于券面额，也不等于商家让利总额 |
| 每月核销率 | 50% | 假设值，须用实际数据替代 |
| 商品佣金 | 0 元 | 未谈成前不纳入基础预测 |

计算：

**9.9 − 2 − 3 × 50% = 6.4 元／会员／月。**

### 6.3 压力测试

| 情景 | 平台补贴 | 核销率 | 每位会员月贡献 |
| --- | ---: | ---: | ---: |
| 基础示例 | 3 元／张 | 50% | 6.4 元 |
| 会员全部使用权益 | 3 元／张 | 100% | 4.9 元 |
| 高补贴且全部核销 | 10 元／张 | 100% | −2.1 元 |

**应尽量让模型在用户积极使用权益时仍能成立，而不是主要依赖忘记领券或忘记取消。**

### 6.4 与微信投流衔接

先按付费队列观察实际贡献，再决定可承担的获客成本。不要把一次付费乘以假定的无限续费月份。

```text
广告队列在已观察期间的贡献
= 该队列实收会员与已结算佣金
− 该队列全部直接服务、试用与权益成本
− 广告获客支出
```

有会员权益后，即使付费转化提高，也要确认新增收入是否超过新增补贴、客服和退款成本。点击率、领券量和签约数都不能代替这项测算。

## 七、连续包月体验与上线检查

### 7.1 收银台示例

```text
经期安心会员
9.9 元／月 · 连续包月〔测试方案〕

本次支付：9.9 元
本期服务起止：展示具体日期
下次扣费日期：展示具体日期
下次扣费金额：展示实际金额

本期权益：AI 增强整理 + 一张自选合作用品券
查看券的完整适用条件

可在“会员管理”中取消后续续费。
另有“单次月卡”可选。
```

不要默认选择连续包月，不使用“免费领取”掩盖扣费授权，不将数据访问或删除权与继续续费绑定。

续费前的提醒、协议内容、取消与变更方式，应根据上线时适用要求和支付渠道能力核验；本节是设计清单，不是对具体业务完成法律审查的结论。

### 7.2 上线前置条件

| 检查项 | 通过标准 |
| --- | --- |
| 主体与类目 | 依据实际功能确认服务类目、广告行业和必要资质 |
| 连续扣费权限 | 实际商户申请通过并完成测试；未通过时只做允许的单次支付 |
| 多端支付 | Android 与 iOS 的购买、续费、退款、权益恢复均在真实设备验证 |
| 通知能力 | 确认可用提醒方式、授权和送达条件，不承诺未经验证的长期自动提醒 |
| 商家权益 | 有明确商品、到手价、库存、有效期与供券协议 |
| 取消与退款 | 用户可独立完成取消；已付权益、已领券、已核销券处理规则明确 |
| 数据与 AI | 最小化收集、权限、存储、第三方处理及生成内容提示完成评估 |

腾讯广告账户资质和投放能力需要按实际账户核实，不能由其他产品已有的能力推断本项目一定获批。[R2][R4]

**在数字服务会员中附送实物商品优惠券，不应被用作改变服务实质或绕过平台支付规则的办法。**

## 八、数据与专业边界

经期、症状等记录可能涉及医疗健康敏感个人信息。应依据实际处理场景落实目的与必要性、保护措施、相关同意和用户权利；具体要求以法律原文与专业评估为准。[R1]

建议采取以下设计：

- **商家只接收交易需要的信息。**不把经期、症状或病史交给商家用于营销。商品收货资料由明确的交易主体按必要范围取得。
- **广告归因不携带健康内容。**即使只是账号标识加会员购买事件，也应评估在健康产品中的敏感性，不能把改名当成匿名化。
- **AI 只辅助记录与整理。**日期与次数由确定性程序计算，生成摘要可追溯原始记录，用户确认后保存。
- **不越界承担医疗用途。**不诊断、不调整用药、不承诺避孕效果，不将推销包装为个性化健康建议。

调用第三方 AI 前，应明确数据范围、服务商、日志、保留与训练用途，并完成适用登记、内容提示及其他要求的核验。使用他人模型不代表应用端无需评估。

## 九、验证路径：逐步放大，而不是先追签约人数

### 阶段一：落实真实权益

先与少量商家谈清优惠、库存、结算、退款和后续供券。使用真实商品下单验证，比较公开渠道同款到手价。

**输出：**权益清单、成本表、真实核销记录、合作责任说明。

### 阶段二：单次月卡验证

可先邀请 20—30 位目标用户开展探索测试。这是建议样本，不是统计充分性或行业标准。

测试工具体验，并区分“AI 会员”与“AI + 用品权益”的付费理由。样本较小时避免把多个变量同时改动后误认为是优惠券带来的提升。

**输出：**首次任务完成、真实付款、券使用、价格感知、退款与客服问题。

### 阶段三：观察重复价值

连续观察两三个付费账期，核实商家权益能否持续、用户是否再次主动购买月卡或持续使用。

**不仅看扣费成功，更看有效记录、主动回访、实际节省和当期贡献。**订阅账期与月经周期不同，应分别统计。

### 阶段四：开放自愿连续包月

在权限与流程全部验证后开放连续包月。比较主动续购与自动续费群组，留意取消、退款、投诉以及不再使用但仍被扣费的情况。

### 阶段五：小额投流，再决定是否扩大

可沿用前述 3000 元作为首轮广告消耗上限示例，不是平台最低充值要求；实际预算应按可承受损失与样本需求决定。

投放真实演示与透明权益，不以健康焦虑或夸张省钱承诺吸引点击。若预算内样本不足，就记录为证据不足；不要为了得到正向结论无限加预算。

## 十、关键指标与暂停条件

| 指标 | 观察重点 |
| --- | --- |
| 首次有效记录率 | 是否完成真实记录并确认，而非仅打开页面 |
| 月卡实付转化 | 明确曝光条件、价格与观察窗口 |
| 自愿签约率 | 用户是否清楚授权，不与实付混用 |
| 领券率与核销率 | 有多少会员真正找到适合的券，以及完成使用 |
| 实际额外节省 | 对比同款、同规格、含运费的可得价格 |
| 跨账期使用 | 是否继续记录、回顾和使用权益 |
| 退款与取消 | 原因、处理耗时、是否存在误导或履约问题 |
| 商家持续履约率 | 承诺权益是否按期兑现，是否出现库存不足或条件变化 |
| 单位会员贡献 | 扣除全部直接成本、权益补贴和退款后再评价 |
| 广告队列贡献 | 区分自然流量与付费新增，不混算效果 |

### 应暂停扩大投流的情况

| 观察结果 | 建议处理 |
| --- | --- |
| 券后价与公开渠道没有优势 | 重新谈供应或调整权益，不继续夸大宣传 |
| 首月便宜、次月无同等权益 | 暂停长期承诺，修订商家合作安排 |
| 用户只领券、工具使用弱 | 单独验证权益业务，不能认定健康工具价值已成立 |
| 付费增加，但补贴后贡献下降 | 调整成本与权益，不只盯转化率 |
| 较多用户不知道在自动扣款 | 立即检查签约与提醒流程，暂停放量 |
| 支付权限、退款或隐私方案未跑通 | 不以扩大用户量替代整改 |

**主题：AI 经期小程序｜会员 + 用品优惠**

**价值主线：记录省心 → 用品省钱 → 透明订阅。**

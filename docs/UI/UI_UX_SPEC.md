版本：V1.1 · 设计基线日期：2026-09-23

本目录保存 **U01—U20原20张主页面图＋S01—S22共22张补充状态板，共42张高清界面图、84个视图**。补图承接首次使用、表单、列表及异常恢复，不增加主路由。本文说明各图对应的用户任务、左右视图、主要操作、页面跳转和异常恢复，供产品、设计、前后端及测试协作使用。

V1.1补充内容见[第9节](#9-首次使用与异常恢复补充设计s01s14)。本次交付是设计与交互规范更新，不表示小程序已经实现或相关业务能力已经开通。

**业务与技术基准：[LunaFlow 小程序技术 PRD V1.0](../report/LunaFlow_小程序技术PRD_V1.0.md)。**设计图用于表达布局、信息层级与关键交互，不是可执行前端，也不是完整状态清单。主图与补图仍未穷举全部加载、权限、支付、库存、退款、弱网和数据不足状态；未单独绘制的适用状态仍须按 PRD 与统一组件规则实现。若图片中的简化文字、日期、数值、图标或状态表达与 PRD 冲突，以 PRD 为准，并同步修订设计，不用图片覆盖业务约束。

## 3. 全局视觉与组件规范

### 3.1 视觉方向

- 暖白作为页面底色，深珊瑚色`#B74752`配白字用于主要动作，淡紫用于辅助信息与解释卡；原`#E97875`仅用于装饰和轻强调。保持低噪声、留白和清晰分组。
- 健康记录区域以用户任务为主，不插入商品瀑布流；权益入口保持可发现，用一张简洁卡片连接服务。
- 页面标题、主结果、金额及主要动作优先；长协议采用详情入口，关键收费、领取、到期及取消规则不能只藏在详情里。
- 状态同时使用图标、文字和必要颜色；不可仅依赖红绿区分成功、处理中或错误。
- 同屏只突出一个主要动作，其余使用次按钮或文字入口；取消、退款和隐私权利不能因视觉弱化而不可发现。

建议把下列视觉值作为组件化实现的起点，最终在真机上统一校准；不要从每张PNG分别取样形成不同主题。

| 设计变量 | 建议值 / 用途 |
| --- | --- |
| 页面底色 | `#FBF9F6`，暖白 |
| 主文字 | `#35343B`，标题及正文 |
| 主要动作 | `#B74752`配白字，两种纯色组合对比约5.20:1；透明度、状态和实际渲染需复核 |
| 装饰强调 | 原`#E97875`只作装饰、轻强调；不再作为小号白字主按钮背景 |
| 辅助信息 | `#EEE9F5`，淡紫背景 |
| 温和状态底色 | `#E4ECE5`，配合图标与状态文字 |
| 卡片圆角 | 16px等效，组件内保持一致 |
| 正文 | 建议16px等效起步；金额、期限与失效规则不以小字隐藏 |
| 可点击区域 | 建议不低于44×44px等效；小程序按目标机型换算并验收 |

在iOS、Android、小屏和大字体设置下验收截断、换行、键盘及安全区。图片背景上的条件说明属于评审标注；正式页面根据真实能力显隐，并保留相应的用户可读规则。

### 3.2 从图片到真实组件

本目录PNG为栅格设计稿，不能作为整张图片贴进小程序代替界面。实现时应建立统一组件和设计变量，重新排版真实文字。

| 组件 | 统一要求 |
| --- | --- |
| 字体与字号 | 使用合法可用且适配目标系统的中文字体栈；统一标题、正文、辅助文字、金额层级；不要复制不同图片的字体细微差异 |
| 图标 | 选定同一套线性图标，统一尺寸、笔画、基线与选中状态；微信原生导航和授权控件依平台实际样式实现 |
| 页面容器 | 统一左右边距、卡片圆角和卡片间距；适配不同宽度、字体缩放及底部安全区 |
| 按钮 | 明确普通、按压、加载、禁用及完成态；提交中阻止重复点击但保留返回和查看状态路径 |
| 表单 | 标签持续可见；占位符不替代标签；就近显示错误并保留原输入 |
| 状态卡 | 统一待确认、已完成、处理中、失败、异常待补救的图文规则 |
| 底部固定栏 | 不遮挡最后一条内容或协议；金额与重要条款位于按钮附近；键盘弹出时布局可用 |
| 商品卡 | 使用真实合规商品图及发布版本；品牌、规格、数量、费用可读，缺货明确 |
| 弹层 | 明确标题、影响、主次按钮；关闭弹层不应意外提交；破坏性操作只做必要确认 |
| 空态与骨架屏 | 加载、暂无数据、无权限、服务错误分开，不用同一空白页混淆 |

图中字符计数、图标细节、圆角和文字换行可能存在图像生成差异。正式页面中的字数、金额、额度、时间和状态均由程序或服务端计算。例如U06的“22/500”只是画面示例，程序须按最终输入与已确定的计数规则实时计算，不照抄数值。

### 3.3 导航与返回

四个Tab为**今天、回顾、权益、我的**，分别对应U04、U08、U10、U14。子页面使用返回导航，不为了复刻图片而在每个子页面重复Tab。广告深链打开子页后，如果没有产品内上一页，返回其所属Tab或U01；退出购买不自动再次弹购买窗。

登录和授权完成后回到原任务，保留已选择方案、组合或正在填写的内容；退出账号清理本地私人健康缓存。不同账号不能看到上一个账号的记录、地址、订单或摘要。

| 用户目标 | 建议路径 | 保留的选择 |
| --- | --- | --- |

## 5. 页面详细说明

### U01 服务介绍

![U01 服务介绍](./U01_service-intro.png)

**目的：**在短时间内说明月度服务包含什么、如何收费及怎样兑现，兼容用品诉求和工具诉求进入的用户。

- **左侧：**页面上部，展示品牌、服务价值、工具/AI/护理三项能力及护理组合入口。
- **右侧：**同页下滑后的规则区，展示每期一次自主领取、到期不累计、配送与售后说明；固定操作栏保持一致。
- **主要操作：**“查看订单并开通”进入U02，仍需查看订单、主动确认必要条款并付款；不是点一下直接扣费。
- **次要操作：**“先体验工具”进入U04；查看组合可进入U11；客服、退款规则进入相关说明或U20。
- **错误恢复：**方案下架、无货或不满足服务能力时不允许继续下单；网络失败可重试，缓存文字不作实时价格依据。
- **验收重点：**收费周期、主动领取及到期规则可读；默认单期主动付款；不假冒品牌合作、虚构折扣或把已付权益叫免费礼品；AI不承诺诊断或预测准确率。

### U02 订单确认

![U02 订单确认](./U02_checkout.png)

**目的：**在付款前锁定本次方案、全部应付、配送地区和关键规则，并取得针对当前报价的主动确认。

- **左侧：**条款尚未勾选，付款按钮禁用；展示服务组成、示例价格、单期主动购买、配送地区及有效期计算方式。
- **右侧：**同页下滑阅读后，用户主动勾选必要交易条款，付款按钮可用。滚动到页面底部本身不等于同意，程序不得自动勾选。
- **主要操作：**“支付¥39.90开通”代表示例金额，实际由服务端报价决定；提交当前报价和确认版本，调起可用支付能力，结果进入U03。
- **次要操作：**修改省市区、查看协议及领取/退款规则、返回U01；售前不收完整收货地址。
- **错误恢复：**报价过期或方案变化时重新展示报价与变化内容，重置相关确认；支付意图未知时先查原订单，不另建重复收费单。
- **验收重点：**首付前显示“付款成功起完整一个日历月”的计算规则，图中具体时点仅为假设示例；成功后才有最终起止。全部约定运费已计入本次报价。购买不要求经期、AI或通知授权。

### U03 支付结果

![U03 支付结果](./U03_payment-result.png)

**目的：**区分已确认付款与仍待核实的交易，给用户下一步而不制造重复收费。

- **左侧：**服务端已确认成功，显示实付、本期起止、领取截止时间和单期购买方式。
- **右侧：**交易尚待确认，显示原订单和金额，说明不要重复付款；不展示成功勾号或已生效资格。
- **主要操作：**成功态“领取本期护理包”进入U10或带本期上下文的U12；待确认态“刷新状态”查询原订单。
- **次要操作：**成功态“开始记录”进入U04；查看订单进入U17；长时间未确认进入U20。
- **错误恢复：**付款成功但发期或资格创建延迟时显示处理中并继续恢复，不能要求再次付款；客户端关闭收银台也不直接等同失败。
- **验收重点：**支付、服务期生效、资格创建均以服务端状态为准；示例本期为09.23 14:30—10.23 14:30；提前续购成功时改为“已付款，待生效”，不能误写本期立即开通。

### U04 今天

![U04 今天](./U04_today.png)

**目的：**让用户以尽量少的步骤完成当下记录，不以每日打卡或停留时长作为价值目标。

- **左侧：**首次无记录，主文案“从今天的一条记录开始”，提供开始、补记和一句话入口。
- **右侧：**已记录9月22日开始，结束尚未记录；主动作变为“记录结束”，保留修改与补记。
- **主要操作：**开始或结束进入U05确认明确日期；“写一句话”进入U06。
- **次要操作：**最近记录进入详情/编辑，回顾进入U08；服务卡未付时进入U01、已付时进入U10。
- **错误恢复：**保存前按需登录及授权；拒绝健康处理可看功能示例和其他独立服务；弱网保留编辑内容，不显示假保存成功。
- **验收重点：**“尚未记录结束”不推断为持续出血；不展示默认28天倒计时；会员卡不遮挡工具任务，基础记录不强制购买。

### U05 日期确认与补记

### 6.2 AI与健康事实

1. 开始、结束、备注和日期以用户确认事实为准；AI提取必须确认后保存，未知保持为空。
2. 时长、间隔和次数由代码计算，AI整理已有事实与来源；不生成疾病、怀孕或疗效结论。
3. 数据不足时展示已有记录及缺少的条件，不用统一28天假装个性化。
4. 修改、删除或撤回处理授权后，相关任务、报告和缓存按PRD失效；不能让旧结果重新发布。
5. 手动降级保障工具可用，但AI作为已售服务内容时不能长期以未接入替代交付；销售承诺与能力必须一致。

### 6.3 账期、领取及主动续购

- 每期按首次支付成功锚定的周年月计算，不按自然月截断，也不随用户生理周期改变。
- 月末不存在原锚点日时裁剪到当月最后一天，后续月份恢复原锚点；由后端计算，前端只展示。
- 首付或断档新购的最终时间在成功后确定；提前续购可明确展示下一期既定起止。
- 已付款未生效、有效可领、已领、到期未领、退款冻结、异常待补救是不同状态，不共用一个“已结束”。
- 正常可兑但到期未领不自动累计是拟定规则，须按发布版本展示；供应、支付开通或领取故障进入补救，不能归为用户忘领。
- 领取提交由服务端校验截止时点、库存、地址与退款保护；已成功受理后跨期仍继续履约。
- 主动续购和自动扣款结果分开统计。未知扣款先核查，不让用户“再付一次”恢复。

### 6.4 供应与销售配置

供应商、实际品牌、规格、可送地区、采购配额、运费、售后和时效未确认前，设计稿不能直接成为投放承诺。生产方案必须完整发布，订单保留购买快照；新配置不能减少已售期权利。

首版三种组合同价、约定配送费用纳入售前报价；不增加领取收费步骤。商品偏好只用已明确的品牌/规格选择，不从症状和周期推断商品。库存在供应商处变化时仍要覆盖已售义务；暂停新销售不能直接关闭已付服务、领取、退款和客服。

### S01 登录与健康用途确认

![S01 登录与健康用途确认](./S01_auth-health.png)

**场景与映射：**U04/U05首次保存私人记录时触发，登录成功仍回原任务；U02需要账户时可复用登录部分，但不能要求健康用途同意。

- **A：登录续接。**标题“登录后保存这条记录”，说明登录用于本人之后查看和修改。主“同意并登录”，次“暂不登录继续浏览”。该确认仅针对页面明确展示的必要账户条款及处理说明，不合并健康、AI、消息或代扣用途；不要求头像、手机号登录、伴侣或身份证。

- **验收：**账户、健康、AI、消息、代扣分别确认。默认不勾选。仅需必要的短期会话草稿，不在未同意时云端长期保存健康内容。

### S05 方案不可售与报价更新

![S05 方案不可售与报价更新](./S05_offer-change.png)

**场景与映射：**承接U01方案暂停、售前不可配送、库存义务不足等情况，以及U02报价过期/变更。

- **A：方案不可售。**标题“本方案暂时无法购买”，根据真实原因给可读说明。禁用付款，提供“查看其他可用方案”（确有方案时）或“先使用记录工具”、客服；不造一个空列表去处。

### S06 确定未付款与已付资格创建中

![S06 确定未付款与已付资格创建中](./S06_payment-recovery.png)

**场景与映射：**补U03的恢复分支，避免“结果未知”“未付款”“支付成功但服务尚在同步”混为一类。

- **A：已核实未付款。**明确“本次订单尚未付款”，解释是否仍可继续原订单。原订单合法可付时主“继续支付”；已经关闭时主“重新确认订单”回U02。用户主动关闭收银台不直接触发该终态，必须有服务端可信结果。
- **B：已付资格创建中。**明确“付款已确认，正在开通本期权益”，展示原单、实付和可确定的服务信息；主“刷新状态”，次查看订单/客服。不能再显示可扣第二次款的按钮。

### S22 已付服务与签约未知/失败

![S22 已付服务与签约未知或失败](./S22_contract-status.png)

**条件与入口：**仅代扣产品已获准且用户主动发起签约时，从U03/U15查看。普通单期购买不必经过此板。

### 10.1 统一验收

视图只在所列服务端条件成立时显示；失败、未知、撤回不能共用一条恢复分支。原单未查清不重复发起外部动作。未绘制状态使用统一组件，可从原订单、隐私任务或提醒入口找回。本节细化需同步进入实现和测试，特别禁止退款渠道失败无条件解冻、未购下一期无条件承诺额度刷新。
